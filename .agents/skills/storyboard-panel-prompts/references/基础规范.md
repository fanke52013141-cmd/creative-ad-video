# 基础规范

根据用户原始提示词整理，并修订内部冲突。本文件与入口、生产方法共同执行；入口列出的适配说明优先。原文存档在仓库资料区，不作为额外运行指令。

将程序预处理后的镜头组 JSON 数据 + 风格圣经文档，转化为一组结构化的分镜板生成提示词。

具体任务边界：
- 输入：一个镜头组的 JSON 数据包（含 shots 数组）+ 风格圣经（style_bible.md）
- 输出：一个或多个分镜板提示词（每板最多 4 个分镜，超出则拆分为多板）
- 目标：每条提示词可直接用于 GPT Image 2 生成一张分镜板长图，画面叙事连贯、风格统一、生成稳定

你不负责：
- 修改原始镜头数据的结构或内容
- 生成视频或动画
- 生成分镜之外的文案、脚本或字幕

你将接收两类输入：

## 1. 镜头组数据包（JSON）

由上游程序从脚本、镜头表、资产表三个文件拼合而成，结构如下：

```json
{
  "video_id": "视频唯一标识",
  "scene_id": "场景唯一标识",
  "duration_seconds": 10,
  "aspect_ratio": "16:9",
  "shots": [
    {
      "shot_id": "镜头唯一标识",
      "role": "first_frame",
      "framing": "景别（远景/全景/中景/近景/特写/大特写）",
      "camera_move": "运镜方式（固定/推近/拉远/横移/跟拍/环绕/升降/手持等）",
      "action_desc": "该镜头的动作与画面描述",
      "assets": {
        "characters": ["角色标识_服装状态"],
        "scenes": ["场景标识"],
        "key_props": [
          {
            "name": "道具名称",
            "is_key_item": true,
            "recurrence_count": 3
          }
        ]
      }
    }
  ]
}
```

关键字段解读规则：
- `role`：按上游接口解释片段位置；不得自动等同整片开场或结尾，不强加视觉钩子与收束
- `framing`：决定主体在画面中的大小和环境信息量
- `camera_move`：提示画面的动态张力方向，转化为关键帧时应选取运镜轨迹中最具戏剧性的瞬间
- `assets.key_props`：`is_key_item: true` 的道具需在应出现的镜头中可辨，权重服从本镜主要信息，不强迫每镜居中
- `aspect_ratio`：若缺失，默认 16:9

## 2. 风格圣经（style_bible.md）

一份综合性视觉风格文档，可能包含：
- 整体视觉风格描述（色调、氛围、质感）
- 品牌视觉规范（色板、构图规则）
- 参考影片/图片及风格关键词
- 光线与色彩倾向

你需要从中提取一句话风格摘要用于提示词的「整体风格」字段，并将其视觉规范融入每个分镜的画面描述中。

对每个分镜板，输出一条完整的提示词，格式严格如下：

---

生成一张【纵向/横向】分镜板长图，从【上到下/从左到右】排列，共【X】个独立分镜，每个分镜均为【16:9/9:16】，所有分镜尺寸一致，紧密排列，分镜之间仅用极细边界区分，不保留文字区，不出现任何文字。

整体风格：
【从风格圣经提炼的一句话风格描述，≤ 30 字，涵盖色调 + 质感 + 氛围】

素材参考：
【仅列真实存在的图片编号与用途；没有图片时写文字规范，不虚构附件。人物、场景、道具可以各有多个参考，按实际来源绑定。】

分镜画面：
分镜1：【景别】，【机位与视角】，【主体描述】，【动作与姿态（定格瞬间）】，【构图位置】，【环境细节】，【光线描述】。
分镜2：【同上结构】
分镜3：【同上结构】
分镜4：【同上结构】

限制：
无文字、无编号、无字幕、无对白框、无水印；不得串格，不得合并分镜，不得遗漏分镜，不无意重复或遗漏；用户要求的回看与重复构图保留，避免人物不一致、服装变化、场景漂移、额外肢体和透视错误。

---

### 格式规则

| 规则 | 说明 |
|------|------|
| 排列方向 | 16:9 画幅 → 纵向排列（从上到下）；9:16 画幅 → 横向排列（从左到右） |
| 分镜数量 | 每板 ≤ 4 个分镜；超出则拆分为多板，板间编号连续 |
| 分镜编号 | 多板时编号连续（板1: 分镜1-4，板2: 分镜5-8） |
| 素材参考 | 若该分镜板中不涉及某类素材，省略对应 @图 条目 |
| 分镜描述 | 每个分镜描述为一个完整段落，七要素齐全，100-150 字 |
| 语言 | 中文，客观精确的视觉描写，禁止抽象情绪词 |
| 多板输出 | 多个分镜板之间用 `===== 分镜板 N =====` 分隔 |


## 分镜组字段与消费者

机器输入的最小契约见[镜头组Schema](镜头组.schema.json)。shots 由本 Skill 消费，shot_id 用于回溯而不是印在图片里；action_desc 用于选取静态关键帧；assets 引用角色、场景与道具规范，不包含从名称推断外观的权限。camera_move 保留原始运动意图，但静帧只表现其中一个可读状态。新增机位或时间字段可以作为扩展保留，不能丢弃用户原始数据。

Schema 只能检查结构与类型，不能证明角色锚点足够、动作连续或视觉可行。重复镜号、关键素材不可访问和相互冲突的状态还需要语义预检。无效输入返回明确字段位置，不把错误内容整理成一份貌似有效的终稿。自然语言镜头表不必先转成接口文件，内部规范化后按同样语义检查。
