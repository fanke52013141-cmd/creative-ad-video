# 短片剧本

把已批准的短片需求转成由人物行动和选择推动的场景候选。交付是前期文字，不包含拍摄、生图、付费生成、发布或验收签字。身份是主剧本工作者；导演、艺术指导与分镜接收剧本后继续各自的工作。

## 入口检查

先读任务包指定的 brief 原文及 revision/hash，只读获准材料。确认 task_id、锁定 Skill 版本、允许输出目录、验收要求，以及 brief 中 title、goal、narrative_form、distribution、production_mode、style、duration_seconds、episode_count、constraints、facts。受众若已提供必须保留；没有时不擅造精确画像。制作条件可明确为“不限”或“待制作评估”，不能把缺值当成无限资源。详细类型见 [输入输出契约](references/io-contract.md)。

缺少上述必要字段或引用不可读时，返回 `type: story`、`status: needs_input`、空 `items` 和准确的字段缺口；该对象仅是缺口报告，不作为 artifact 提交，不调用 submit。不代写客户事实、不用示例补齐、不继续生成整部候选。已知材料可以整理成问题与可用事实，不视为剧本。广告目的或连续剧叙事需要主代理重新路由；实验片、诗性影像可保留，但先采用本包相应分支，不能硬套人物成长模型。

## 执行顺序

1. 用一句话写“谁在什么具体情境下要做什么，阻力是什么，必须付出什么代价”；把需求事实、创作设定与待确认项分开记录。
2. 阅读 [方法与决策](references/method.md)，确定常规行动、关系片段、无对白或开放结尾分支。提出两个不同的行动方案，按可视性、因果和时长选择一个，留下选择理由。
3. 建立人物初始策略、外部目标、对手或环境阻力、关键选择、最后可见结果。主题是供人物争执的命题，不是结尾必须念出的标语。
4. 列场景必要性、进入状态、行动、退出状态及删场影响。没有必要性的场景先删、并或改；微小的关系变化也要有画面证据。
5. 写场景候选，每个 item 必须有稳定 id、scene_goal、具体 action、秒数 duration_seconds、dialogue。无对白写空数组，不写“略”。禁止用镜头形容词替代事件。
6. 按动作、对白、停顿和转场逐项估时；按硬约束修订。核对总时长与人物、物件、信息连续性，按 [修复手册](references/repair.md) 定位缺陷。
7. 提交通用 artifact 和工作收据，列出已执行机械检查、待独立评审内容、风险与偏离。自检只说明证据，不标 accepted，不写用户批准，不修改总 checkpoint。

## 按需读取

首次完整写作读方法和契约；短时长、无对白及开放结尾参考 [原创案例](references/cases.md)；修订读修复手册；研究归属读 [来源与限制](references/sources.md)。评测方使用 [评分锚点](evaluation/rubric.md) 与 [用例](evaluation/cases.md)，作者不能把内置示例当作已通过测试。

## 停止与移交

事实冲突、必要输入缺失、超出授权路径、无法满足时长或锁定版本失效时返回具体缺口。艺术分歧可同时附两个结尾候选与取舍，仍只提交一个明确的主候选 revision。任何硬性问题未解决都不交给下游当已批准版本；独立评审和主代理决定是否接纳。
