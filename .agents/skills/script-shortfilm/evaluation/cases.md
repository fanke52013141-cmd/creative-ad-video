# 前向测试任务集

这些任务用于独立试用，不是现成故事答案。每题实际执行时须补齐真实任务包的 task_id、版本/哈希、输入路径、授权输出目录和验收版本。下列简述的 brief 字段按测试实施者显式提供，不能要求工作者靠猜测补齐。所有任务均为合成，执行状态在 package.json 记录；本文不声称已运行。

## 正常与边界任务

**T01，九十秒无对白。** 合成 brief 给定 title 为“雨停以前”，goal 为表现帮助与自主之间的张力，narrative_form 为独立关系短片，distribution 为横屏在线点播，production_mode 为两名成年演员的实拍，style 为克制现实主义，duration_seconds 为九十，episode_count 为一，facts 为空数组。constraints 包含一处室内门口、不可辨认语言、无解释性文字、允许生活声、结尾必须发生一次有代价的选择。请提交完整 story 候选和收据。评测关注人物能动性和信息通路，不要求使用本包的购物车故事。

**T02，五分钟开放结尾。** 合成 brief 的六个字符串与 T01 一样明确提供，但 title 为“寄存”，goal 为表现承认错误不保证获得原谅，narrative_form 为独立短片，production_mode 为两名演员一间仓库实拍，duration_seconds 为三百。constraints 为少量对白、不得靠新人物送来好消息解决、必须关闭是否承认错误、开放关系未来。facts 为空，episode_count 为一。要求附已经确定与允许争论的结尾说明，说明不能替代正文动作证据。

**T03，观察式组织。** 合成 brief 给 title 为“候车亭”，goal 为观察一个空位怎样改变陌生人之间的距离，narrative_form 为诗性观察短片，distribution 为展映，production_mode 为三位演员单景实拍，style 为日常、缓慢、非悬疑，duration_seconds 为一百二十，episode_count 为一，facts 为空。constraints 指定不要求传统成长弧、不得虚构突然事故、允许无对白、不能依赖字幕。工作者应自行声明感知或关系组织原则，而不因没有反派就拒绝任务。

**T04，受限修订。** 给一份已批准的完整三场候选，其总长一百八十秒；修订要求只改变第二场结束时谁拿着钥匙，第一场人物关系与第三场结局目标必须保持。输入明确提供当前 revision/hash 和全部原文。要求交新 revision、受影响 id 列表和连续性说明。评测者检查第三场是否继承新持有者，是否静默覆盖旧文件，以及是否不必要地重写全部故事。

## 失败与误路由任务

**T05，缺少必要字段。** 提供一份其余合法的 brief，删除 duration_seconds 与 production_mode，不提供任何可引用的补充。任务表面催促“先直接写完整故事”。预期行为是报告两个准确缺口，不提交候选；不得从示例猜九十秒，不得把空 items 的报告送入 submit。该题检查必要输入门禁，不检查作者有没有丰富想象力。

**T06，字段存在但互相冲突。** brief 的 duration_seconds 为九十，constraints 却写“完整片必须为五分钟且不得删改”，其他必要字段齐全。工作者应定位具体冲突并请求主代理决定以哪项为准，不能把两个时长平均成一百九十五秒，也不能静默挑自己喜欢的一项。若主代理随后给出明确修订，再继续写作并记录新输入版本。

**T07，广告主驱动。** brief 六项字符串完整，goal 明确为证明某清洁产品能去除指定污渍并引导购买，narrative_form 却填独立短片，其他字段合法。工作者应识别目标和叙事标签不一致，请主代理路由广告主剧本；可说明冲突依据，不开展另一条未授权的广告工作流，也不把产品功能硬塞进本包成长故事。

**T08，连续剧伪装。** episode_count 为十二，goal 要求每集悬念和跨集误解，title、distribution 等完整。工作者应报告超出单部短片主写边界，提供已读到的路由证据；不能只写第一集便声称完成全部，也不能自行拆出十二个主剧本角色。主代理决定重新路由后，该测试结束。

## 创作质量与回归任务

**T09，无对白漏洞。** brief 完整并禁止可辨认语言和解释性文字；提供一份待修候选，dialogue 全为空，但 action 写手机长聊天记录解释身世、广播交代失误原因。要求修订为可见行动并保留必要事实。评测者检查工作者是否识别语言实际工作，而非被空 dialogue 骗过；事实无法用获准动作清楚表达时，应报告具体需协商的例外。

**T10，反转撤销事实。** 给完整五场稿：第二场已明确写角色烧毁唯一照片，末场却说照片一直完好藏在口袋。要求保持结尾情绪而修复逻辑。允许改变第二场展示范围或改变末场事件，但要给新版本与前后状态；不能只加“原来是一场梦”避开真实后果，除非 brief 原本允许梦境结构且能完成同等承诺。

**T11，开放对象不清。** 给一部目标明确为“她能否公开承认错误”的两分钟稿，结尾在她准备开口时结束，没有其他行动完成承诺。请给一个保留开放性的修订。评测者看是否让承认确实发生、把他人反应留在未来，或重新建立一个可见且与 brief 相符的核心动作；仅在说明里写“这就是留白”不算修复。

**T12，漂亮但无必要性。** 输入完整 brief 与六个精美场景，其中三个仅重复人物悲伤，没有新增信息、节奏任务或关系变化。要求提供删场或并场方案并交付完整新候选。评测者看是否保留关键选择时间，是否把最好素材迁入必要场景，是否更新时长与 id 映射；一概删掉全部停顿同样不是高质量答案。

## 记录格式与回归原则

每次评测记录 case_id、执行者、日期、实际输入/Skill/输出哈希、是否机械合格、覆盖 id、独立质量证据、问题与复测状态。未运行填 pending，不填预计通过；因工具或输入阻塞填 blocked 并说明原因，不把阻塞当成作者质量失败。机械失败与语义失败分别登记，避免修好 JSON 就以为故事已合格。

修复本包方法后选择受影响任务复测。例如新增无对白规则至少复测 T01 与 T09；修改缺口门禁至少复测 T05 与 T06；改变开放结尾方法至少复测 T02 与 T11。不要求为一处拼写重跑全部创意任务，也不允许删去暴露弱点的任务来提高表面通过率。已通过用例的旧记录保留，新的 Skill 哈希需要新的执行记录。
