# Video Flow 宿主接口契约

版本：0.2.0草案。Python CLI管理任务、契约、状态与交付；宿主负责实际工作者执行、工具调用和用户交互。生成task packet不等于已启动Agent；mock宿主通过不等于目标产品通过。

## 1. 能力探测与证据

目标宿主接入前记录产品与安装版本、插件/工具清单、运行平台、可用文件范围和执行日期。探测不调用付费图像生成。每项能力记录available/needs_input/unsupported以及工具返回的实际证据：

| 能力 | 必需行为 | 证据 |
| --- | --- | --- |
| 文件与CLI | 读取指定packet、锁定Skill、素材；在指定位置写候选与回执；执行CLI | 正常读写与越界约束说明、命令退出码 |
| 独立工作者 | 使用新上下文启动作者与不同评审，传入必要材料 | 实际spawn结果、真实worker ID、任务对应关系 |
| 等待与取消 | 等待完成/报错；用户中断时保留状态，恢复后先检查旧任务 | 实际等待/取消结果与checkpoint |
| 图片查看 | 解码并向评审呈现指定图片及参考图 | 图像工具输出、被查看路径/hash、可见内容结论 |
| 身份回执 | 从真实工具结果获取ID，bind后写回执；禁止手工制造Agent | bind记录与receipt中的一致身份 |
| 用户决定 | 展示具体版本，记录用户明确批准；automatic遵循初始化选择 | 批准对应产物hash与用户决定来源 |
| 图像来源 | 生成通道支持所需参考图或明确导入；预算与来源可审计 | capability/profile、实际请求/导入记录 |

无法独立启动评审的宿主不应通过“同一作者换一句角色声明”补齐能力。无法看图时媒体审查返回needs_input；文件存在、模型返回成功或Pillow解码不代表视觉已审。

## 2. 调度协议

1. 执行protocol并读取当前run的status/audit；只从ready阶段派发，不直接编辑checkpoint。
2. dispatch产生packet后，以新上下文启动任务。传packet绝对路径、锁定Skill与任务必要规范；v0.2参考docs/contracts-v02.md，旧任务继续原契约。
3. 从真实宿主返回值取得worker ID，bind到task_id，并将绑定结果告知工作者。回执按候选实际字节计算hash，禁止抄写或替作者伪造。
4. 等待结果后submit，由程序检查回执和候选；创建review时使用新的独立身份。评审指标精确来自packet，不能私自简化。
5. revise返回原项与具体反馈，重试在预算内。超时先确认旧任务与外部请求状态，不重复提交状态未知的付费请求。
6. awaiting_approval展示具体作品及版本后收取决定；automatic模式仍经过独立review。
7. 全部适用阶段accepted后，执行交付审计、导出与verify-package。制作包完成时保留平台绑定待执行、视频结果未验证。

宿主仅能并行互不依赖的ready工作。一个媒体任务一张图、一项回执；不能为了节省调用把多个资产或多个板任务合并。任务最小化仍须保留当前片段全部源镜、真实参考和必要前后状态，不能只传上游自由摘要。

## 3. 已有输入与导入身份

真实worker ID来自宿主执行工具；import actor表示确定性文件登记操作。两者必须有明确的执行者类型、operation_id、来源路径/hash与审计规则，不能把`import:某字符串`作为一个实际Agent传给bind。

在专用导入命令尚未实现/验证的环境中，已有素材由明确任务的真实工作者登记并照常审查，或标记needs_input。任何路径都不直接跳过review，不把“文件由用户提供”解释成“本版本已获批准”。

## 4. 验收与兼容状态

每个真实宿主至少执行：单作者任务、独立评审、错误回执拒绝、工具失败恢复、图片查看、完整合成制作包导出与跨目录复验。证据记录工具版本、真实ID、packet/hash、退出码、状态转移与最终包检查报告。

接入状态分别为verified、needs_input或unsupported。verified仅对应实际测试的版本和配置；协议测试不证明真实图像创作质量。共享文件系统内的身份标签与写入约定属于验收机制，强制隔离和认证需宿主权限支持。
